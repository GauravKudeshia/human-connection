# V1.3 Release A — engineering changes and verification

## Resolved defects

- **Paid READY lock:** checkout snapshots `joinDeadlineAt` from trusted demo runtime configuration (default 180,000 ms). Every read/action checks it. Expiry creates one automatic full base reversal, one resolved refund record and one audit event, retains historical charges, and releases the host. A rejected late join still persists expiry in both browser and D1 transports. A same-key checkout retry cannot reopen the booking. Old READY records receive the policy from their original paid time.
- **Ratings on non-delivery:** only COMPLETED, paid simulations accept a normal host review. Repeated edits keep one logical review per booking. Cancelled/failed/partial sessions use `service-feedback`; refund feedback has a separate field and action. Legacy invalid ratings migrate to separate feedback instead of being silently discarded or advertised as host reviews.
- **Refunded tip receipts:** `receiptFor` provides original base charge, base refund, original tip, tip refund, final net, session status and payment status. Unpaid quotes are not represented as charges. Refunds reverse recognized base earnings and confirmed tip principal through balanced compensating entries, without rewriting earlier journal groups.
- **Mismatched reports:** report creation validates the host, optional booking existence and host/booking relationship before saving a case or ending a session.
- **Incomplete overlap recognized as completion:** automatic deadline handling only recognizes full delivery after a full simulated overlap. A long disconnect followed by a last-second reconnect ends as partial delivery and opens review. The explicit “Finish demo” shortcut remains labeled and marked as a simulation.
- **Replay/privacy edge cases:** SHA-256 replay comparison replaces raw payload duplication; existing replay records migrate compatibly. Prototype-property keys are stored as harmless own properties. Closure clears report/operator/refund narratives and feedback while retaining the demo financial history.
- **Malformed API body:** JSON null and array inputs return controlled 400 errors. Origin, media type, length, owner-scoped parameterized queries and optimistic write checks remain.
- **UI focus and layout:** extracted stable host cards remove the timer-driven remount; native modal focus is restored, Escape works, step changes receive focus, and phone controls/labels/typography are enlarged. The directory/sidebar-first screen is replaced with consumer navigation and a guided moment flow.

## New behavior

`lib/matching.mjs` ranks eligible fictional hosts deterministically. `match` creates the reservation atomically in the same engine action, recomputing availability after expiry. Experience, style, language, format, blocks, closed accounts, operations pause and existing requests are checked. Fairness counters update only for a successful local reservation.

`lib/activities.mjs` provides nine authored sample activities, three per experience. `select-activity` accepts only a matching experience and a preparing/live/reconnecting demo booking. Selection survives same-tab reloads; clearing it is allowed. It creates no human response or media connection.

The public and private prototypes share the same engine and UI. The public build remains a self-contained `docs/index.html`, published through the existing `main /docs` GitHub Pages setup. No backend provider or Sites-hosting audience change is introduced.

## Component boundaries

- `app/connection-app.jsx`: request/state orchestration and consumer navigation.
- `app/components/landing.jsx`, `moment-finder.jsx`: home, experience/style choices and matching preparation.
- `host-browser.jsx`, `host-card.jsx`, `profile-dialog.jsx`: directory, stable cards, written intros and direct booking.
- `booking-options.jsx`: reusable time/format/language choices and demo acknowledgement.
- `session-flow.jsx`, `activity-panel.jsx`: booking/checkout, explicit room simulation, post-session feedback and tips.
- `receipt-panel.jsx`, `session-history.jsx`: receipt projection, refunds, history and rebooking.
- `host-studio.jsx`, `operations.jsx`: preserved fictional host/staff tools.
- `app-modal.jsx`, `shared.jsx`: support/account/report/application forms and accessible shared primitives.
- `lib/demo-policy.mjs`, `matching.mjs`, `activities.mjs`, `receipts.mjs`, `fingerprint.mjs`: shared rules and projections, separately testable.

The browser entry is `pages/entry.mjs` rather than a JSX Pages Router route, so the optional server no longer advertises an unintended `/entry` page.

No general-purpose AI system, dependency-heavy recommendation model or production payment/video implementation was added.

## Browser validation

The browser walkthrough used fictional test activity only and completed these checks:

- Experience/style selection, keyboard duration selection, back-navigation preference preservation and first-request acknowledgements.
- Deterministic matching (Playful Banter → Daniel), 30-minute $18 checkout, explicit join deadline, optional activity selection and reconnect without resetting the clock.
- Completion, editable single host review, custom $5.50 tip, Operations approval of a full base/tip refund, and receipt showing $18 charge / −$18 refund / $5.50 tip / −$5.50 tip refund / $0 net.
- Small-phone no-match explanation for a Spanish Make Me Laugh request; changing choices then successfully checking out a 15-minute $10 video simulation.
- Real three-minute wait while other QA continued: READY automatically became EXPIRED, showed the reversal message, and returned the host to discovery. No test-only clock manipulation was used for this browser check.
- Host search, saving Maya, profile written introduction, account-independent same-tab reload persistence, host studio and Operations journal views.
- Native dialog Escape dismissal restored focus to the invoking button; reverse tab navigation stayed inside the dialog. Keyboard Enter selected rating/time/favorite controls. No camera or microphone prompt occurred.
- No horizontal document overflow at **320, 390, 768 and 1440 CSS pixels** on landing, style choice, time/format, host browsing, booking/checkout, room/activities, post-session, history, host studio and ledger. Profile and receipt dialogs also had matching client/scroll widths at all four sizes. Screenshots were visually inspected at desktop and small-phone sizes; the detected homepage caption overlap was corrected and rechecked.
- Browser console warning/error collection returned **no entries** during the checked journey.

This was desktop-browser viewport emulation and a focused keyboard walkthrough, not a claim of physical-device coverage, all-browser compatibility, exhaustive screen-reader evaluation, load testing or production provider certification. Automated domain tests cover the additional failure/duplicate/migration paths.

## Run and preview

See `README.md` for commands. The quickest preview is `npm run build:pages` followed by `npm run preview:pages`, then open `http://127.0.0.1:4195/`. The downloadable `docs/index.html` also works in a browser without a server. Public demo state stays in the visitor’s tab; no real card, call or staff response occurs.
